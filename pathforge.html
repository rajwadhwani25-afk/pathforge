HOW IT WORKS

The backtracking algorithm starts from node 0 and tries to extend the current path one node at a time. If it hits a dead end, it backtracks and tries a different neighbor. This continues until either a complete Hamiltonian path is found, or all possibilities are exhausted.

Understanding Hamiltonian Paths

A visual, interactive guide to one of graph theory's most fascinating problems — from basics to real-world applications.

⬡ HAMILTONIAN PATH

A Hamiltonian Path is a path in a graph that visits every vertex exactly once. It doesn't need to return to the starting point.

Named after Sir William Rowan Hamilton who invented a puzzle involving finding such paths on an icosahedron in 1857.

A → B → C → D → E (visits all nodes once)

◎ HAMILTONIAN CIRCUIT

A Hamiltonian Circuit (or cycle) is a Hamiltonian path that also returns to the starting vertex, forming a closed loop.

Every complete graph Kn where n ≥ 3 has a Hamiltonian circuit. Finding one is the basis of the famous Travelling Salesman Problem.

A → B → C → D → E → A (returns to start)

ORE'S THEOREM (1960)

If for every pair of non-adjacent vertices u and v in a graph G with n vertices, the condition deg(u) + deg(v) ≥ n holds, then G has a Hamiltonian circuit. This is a sufficient (not necessary) condition.

REAL-WORLD USES

Logistics routing, DNA sequencing (genome assembly), circuit board drilling, knight's tour on chess, scheduling problems.

WHY NO SOLUTION?

A graph with a "bridge" vertex of degree 1 cannot have a circuit. Disconnected graphs have no path. Odd-degree nodes in Eulerian terms differ from Hamiltonian constraints.

vs EULER PATH

Euler paths visit every edge once. Hamiltonian paths visit every vertex once. Very different problems with very different algorithms!

COMPLEXITY

No polynomial-time algorithm is known. It's NP-complete. For n nodes, brute force checks n! paths. Even heuristics like dynamic programming run in O(2ⁿ·n²).
